# Model/checkpoint trust and executable deserialization — decision procedure

## Establish the boundary

Trace artifact publisher/source/digest and user-controlled selectors into loader options, import hooks, deserializers and device/resource handling. Record framework/version defaults and whether the consumer can execute code or allocate resources before validation.

## Smallest decisive verification

Prefer source/configuration and safe metadata inspection. If necessary, use a locally authored inert constructor marker in a disposable harness with no network or real credentials; never load an unknown model to find out whether it is dangerous.

## Reject or narrow unsupported conclusions

Weights-only or a filename extension is not a universal sandbox. A valid signature proves a publisher assertion, not safe content or recipient authorization. A changed framework default does not prove an application overrides or actually uses it.

If the boundary is absent, record not-applicable and the reason. If an artifact/access requirement is missing, name that missing decisive check and keep the hypothesis unverified. Observed behavior must match the claimed actor/build/resource; a fixture only proves its encoded boundary. Stop on unexpected unrelated effects or degradation.

## Repair acceptance

Constrain artifact identity and supported nonexecutable formats/loader behavior, with bounded isolated processing and explicit code trust where unavoidable. Retest legitimate models, rejected unsafe types/sources and absence of pre-rejection effects.

## Evidence worksheet

framework/runtime/options; artifact identity and publisher trust; reachable selector; constructor/import path; safe static or inert marker evidence; resource limits and normal load control

Each result should explain the intended policy, caller control, actual consumer, result and competing explanation. Severity follows the evidenced consequence and prerequisites, not the technique label.
