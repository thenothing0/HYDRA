# Browser execution context, content control and consumer

Analyst decision guide for this family. Use the questions relevant to the actual skill/target; this is not a certification checklist or evidence that any check occurred.

Map who can place content, who encounters it and the actual HTML/attribute/URL/script/message/storage context. Preserve original bundle/document evidence and browser/build identity. Treat source maps and discovered endpoints as inventory until reachability and a protected consumer are established.

Separate browser-enforced properties from application choices: origin/peer, cookie delivery, CORS-readable response, framing-sensitive action, service-worker controller and a transferred port's capability. Reproductions need the actual browser behavior when that behavior is central; a same-page manually dispatched event is not a foreign-origin message.

Use harmless DOM/data markers and two owned identities/origins where needed. Escaped reflection, self-only script the actor is already allowed to run, public cross-origin data and a wildcard carrying nonconfidential messages may be intended. Do not turn every missing header into a finding.

Fix the precise context/authority boundary using supported encoding/sanitization, peer/action checks or lifecycle isolation. Confirm valid rich content/integration/offline behavior as well as the denied effect. Browser emulation and static source traces retain their limits.

## Evidence before conclusion

- placement actor and encountering viewer
- actual browser origin/peer/controller and consumer context
- input-transform-sink trace with original provenance
- inert effect versus reflection or intended public behavior
- required integration and valid-content controls
