# Single-finding handoff

Keep one independent issue per file. Record affected asset and owner, evidence IDs/redacted artifacts, intended rule, actual observed effect, prerequisites, reproduction, contextual severity, source-supported root cause, remediation and test limits. Link related issues explicitly and flag shared root causes for review; do not silently merge or duplicate reports.

Discover the responsible owner’s published security/VDP page or current program brief. Use security.txt only as a contact/policy pointer, not testing authorization. Verify the exact asset, vulnerability exclusions, program state and access requirements, cite current official sources, and leave the route unresolved if evidence is missing or contradictory. Do not guess security email addresses or submit to a convenient platform unrelated to the owner.

Format for the actual program template and preferred language. Include missing information as draft blockers rather than inventing reproduction, eligibility, CVSS or custom fields. The user can explicitly authorize an actual submission in a separate or existing instruction; this handoff by itself only prepares local report content.
