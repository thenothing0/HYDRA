# Provider-specific effective authority and deployment state

Analyst decision guide for this family. Use the questions relevant to the actual skill/target; this is not a certification checklist or evidence that any check occurred.

Identify the exact provider, principal/session form, resource hierarchy, action and conditions. Collect applicable inherited and local policies, grants, boundaries, admission/network controls and credential issuers. Unknown layers remain gaps. AWS, GCP, Entra, Firestore and Kubernetes are not interchangeable allow/deny models.

Prefer source/configuration and authorized read-only evaluation. Distinguish a policy prediction, a dry-run and a real bounded synthetic resource operation. Rendered configuration, admitted configuration and running enforcement can differ; collect the relevant version, CNI, node OS or SDK path.

Broad-looking permissions may be intended administration or constrained elsewhere. A disabled setting, cloud project identifier, client key or network connection alone does not prove private-data access or escalation. Establish every permission and consumer needed for a delegation chain without creating privileged live resources.

Fix the effective policy/capability at the right owner boundary and preserve required service use. Retest denied/required tuples, lifecycle and convergence. A customer configuration defect is reported under that customer's policy; provider branding alone does not make it eligible for the provider's program.

## Evidence before conclusion

- provider/version and principal/resource/action/context tuple
- complete relevant policy/hierarchy and missing layers
- rendered/admitted/running or evaluator-versus-operation distinction
- synthetic protected effect and actual consumer authority
- required workload and denied-tuple retests

Use the technique-specific guide and current primary runtime/provider documentation for details. If a decisive requirement is unavailable, record the missing artifact and narrower supported conclusion.
