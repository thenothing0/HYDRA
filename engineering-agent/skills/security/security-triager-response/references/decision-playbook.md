# Report claims, reproducibility, routing and recipient isolation

Analyst decision guide for this family. Use the questions relevant to the actual skill/target; this is not a certification checklist or evidence that any check occurred.

Reconcile every title, prerequisite, step, impact and severity with evidence for the same actor/resource/build. Inventory, source proof, dynamic observation and a proposed escalation are different claim strengths. A triager must be able to reproduce without guessing setup hidden in a video.

Keep one report per independent cause and per-recipient attachments. Link shared causes and chain edges explicitly; incompatible roles/versions or a missing capability leave composition unverified. A patch or an expired fixture account is not a successful retest.

Verify the affected owner, exact asset, current program state/access, exclusions, preferred template/language and severity method. A security.txt pointer, brand name or generic platform profile is not scope/ownership evidence. Program policy overrides generic field defaults; unresolved route evidence keeps a neutral draft useful.

Correct overstated claims and respond to concrete triage questions using existing evidence before collecting more. Do not invent private duplicate-report content, translate without source accuracy or promise a reward. Report completeness and hashes cannot establish factual validity. Transmission and platform-state changes follow explicit user authorization, including any already supplied.

## Evidence before conclusion

- finding ID, independent cause and evidence-supported claim
- reproducible actor/setup/build and paired controls
- actual impact, severity rationale and missing proof
- current owner/program route and recipient-specific artifact review
- technical retest state versus proposed platform action

Use the technique-specific guide and current primary runtime/provider documentation for details. If a decisive requirement is unavailable, record the missing artifact and narrower supported conclusion.
