# Follow-up output contract

Markdown-only manual workflow; no executable helper or platform API is required. Create one local draft per original finding with its original ID, source dialogue, current evidence, proposed technical outcome and explicit limits. Keep report state as an observed fact or a proposed draft action, not an action claimed to be performed.

Reference redacted artifacts by stable IDs and hash the actual delivered bytes with an available local tool when needed. Do not copy attachments between private programs or recipients. Clearly label new evidence, changed claims and unavailable checks. If the host lacks runtime access or the user supplied only a patch/dialogue, produce the useful static/draft result with that limitation.

The package assessment plan command is not applicable to this follow-up skill because it is not a vulnerability-discovery catalog. Use assets/followup-template.md manually. Existing reporting helpers remain optional; this skill does not claim to extend their input schema or automate a platform state transition.

No external messages, uploads, report-state changes, paid retest acceptance or disclosure are authorized by loading this skill. Follow any explicit user authorization for a concrete external action separately and verify its recipient/policy at that point.
