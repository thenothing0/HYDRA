# Assessment selection, action authority and honest coverage

Analyst decision guide for this family. Use the questions relevant to the actual skill/target; this is not a certification checklist or evidence that any check occurred.

Turn the user's actual request and existing authorization into a bounded assessment brief. Record system components and trust boundaries, evidence/access available, deliverable and relevant policy. Do not ask again for authority already clear in the session.

Select specialists by decisive boundary and prioritize reachable sensitive invariants. Do not run every skill or tool because it is installed. Route JS inventory into the relevant server/browser assessment, 403 into a protected-effect comparison, and cloud/native questions into their actual provider/ABI model.

An untested domain is not clean, and a domain absent from the system is not a failed test. Label performed, not-assessed and not-applicable with evidence and a reason. Keep policy ambiguity, missing runtime identity and unsupported tools as specific gaps while continuing independent authorized work.

Deliver the useful reports, remediation/retests and coverage ledger for the requested scope. A large test count, comprehensive folder inventory or a loaded skill does not certify vulnerability absence or agent decision quality. No delegation, external transmission or continuing surveillance is implied by coordination.

## Evidence before conclusion

- requested mode/deliverable and existing authority
- asset/actor/boundary ledger with selected specialists
- evidence access and smallest decisive checks/disproofs
- budget/stop condition and independent work while gaps remain
- coverage states, report/retest handoff and residual limits

Use the technique-specific guide and current primary runtime/provider documentation for details. If a decisive requirement is unavailable, record the missing artifact and narrower supported conclusion.
