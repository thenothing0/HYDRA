# File identity, containment, processing and publication

Analyst decision guide for this family. Use the questions relevant to the actual skill/target; this is not a certification checklist or evidence that any check occurred.

Follow input through admission, canonical path selection, storage ownership, extraction/processing and retrieval. The filename, MIME label, parser-selected format and final published bytes can differ. State the intended root and which actor controls names, links, overwrite targets and downstream reads.

Use tiny local fixtures and inert output/worker markers. Establish actual resolved destination/object identity before claiming traversal or link escape; textual prefixes do not prove containment. An extension check is not a worker sandbox and a converter policy file is not necessarily the active policy.

Review bounded byte/file/count/work limits before costly operations, temporary ownership and cleanup after failures. Existing files, partial extraction and asynchronously published output can change security after an error. Never extract unknown hostile archives or exploit documents on a shared live host for demonstration.

Repair admission and authoritative write/processor/delivery boundaries. Retest normal files, denied outside-root/owner/capability cases and unchanged external state. Explicitly separate deterministic path checks from untested concurrent filesystem races or full decompression performance.

## Evidence before conclusion

- intended root/owner and actual file/format identity
- entry-normalization-write/process-delivery trace
- link/parent/overwrite and worker authority
- tiny fixture contents, output and outside-state evidence
- resource/cleanup and legitimate-processing controls

Use the technique-specific guide and current primary runtime/provider documentation for details. If a decisive requirement is unavailable, record the missing artifact and narrower supported conclusion.
