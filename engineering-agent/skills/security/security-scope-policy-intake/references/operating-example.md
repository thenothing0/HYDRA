# Preserve authorization and isolate the missing constraint

## Example: sufficient authorization already exists

The user authorizes two owned staging accounts, synthetic documents and bounded export tests. Record that authorization, asset/build and the permitted account/data operations, then proceed. Do not demand fresh permission for every reversible step or treat a public scope page as revoking an explicit valid instruction. If production/CDN/vendor assets are outside the stated engagement, keep those as evidence leads rather than extending tests there.

## Example: one constraint is missing

A program allows web testing but the proposed check needs concurrent state-changing requests. Read the supplied/current policy for concurrency/automation rules. If those rules decide whether the method is permitted and remain unknown, ask only about that method or use a source/local alternative. Continue independent code review/report drafting. No answer or elapsed time is authorization for the dependent action.

Keep owner policy, program eligibility, testing authority and transmission authority distinct. security.txt can identify contact policy but does not itself grant testing permission. Record precise asset, actor/data, method/rate, time/environment and disclosure constraints relevant to the proposed action; avoid a long intake form when the session already supplies them. Deliver actionable permitted work and the exact blocked edge, not a generic safety checklist.
